Github Pages+Hexo博客搭建

2026-04-10
CS杂项
2.7k words
  • Blog
  • Hexo

上个学期在前辈的推荐下想要搭建一个自己的博客，当时还是一个信息收集和抽象归纳能力都很羸弱的小白，一番折腾之后迟迟没有搭建出一个稳定可用的框架。现在稍微有了一点时间，决定还是把流程和配置都简化，至少做出来一个可以用来堆积笔记的小仓库。所以今天来写一个技术栈梳理+部署流程的总结（重点在于经验总结，不在于部署流程，极速版配置流程可参考配置教程和使用教程

技术栈

运行基础/前置知识

从上到下分为三层

1.环境层

  • Node.js（运行时环境）
    Hexo 是基于 Node.js 开发的，需要其提供的JavaScript运行环境提供支持
  • NPM（包管理器，Node.js自带）
    基于上述内容，npm可用于安装Hexo核心包与插件，一些主题也支持使用npm命令进行下载

2.框架层

  • Hexo（页面渲染生成工具）
    结合主题配置文件与markdown文件，将一般文本渲染为一套美观有固定格式的静态页面，并与Git等工具对接完成博客内容的更新。

3.部署控制层

  • Git（本地版本控制工具）
    本地代码库，可以进行仓库版本更新与回滚，在这里主要起到一个代码搬运的作用，将Git与Github完成登录连接（推荐使用ssh方式）即可使用gitbash将代码更新到个人账号下的指定仓库
  • Github（云端部署平台）
    此处介绍内容分为存储静态网页的Repository（仓库）和Github Pages两个部分

Repository 用于存放本地工作文件夹中public的内容（由Git实现，后面会讲），存储了网站的前端代码。以username.github.io命名，作为用户站点的唯一表示。

Github Pages是Github提供的静态站点托管服务，用于建立属于个人的网站，提供免费的服务器空间与域名。当建立好以 username.github.io 命名的repo时，便可以使用 https://username.github.io 这个域名来访问，如果有需要还可以买个自己的域名，指向利用GithubPages建立的站点即可

在我部署博客的过程中发生了什么？

  • 前提：Git与Github已完成连接，安装好Node.js环境
  • 流程：进入本地工作文件夹->利用npm下载好Hexo框架->在本地文件配置好主题、博客文章（Markdown文本）->在配置文件中指向网页repo，将Hexo渲染好的静态代码放到本地的public文件并通过Git工具提交到repo->站点更新，博客上传成功

一些常用命令

结合Obsidian+Shell Commands插件进行自动化

配完了主题以后，在Gemini大师的启发下决定使用知名markdown编辑器Obsidian进行一个写博客的流程优化，实测用起来也是非常爽，可以实现不开命令行窗口就能完成写作+部署全流程，分享一下我的改造流程

改造过程

一些前置知识

我们都知道，博客文章都放在source/_post目录下,图片等资源也最好新开一个images文件夹来存放。于是我们可以使用Obsidian打开source文件夹作为一个封闭的空间管理博客文章 （注意一定要仓库一定要建在source下，原因是如果直接深入到_post文件夹会导致图片资源以及草稿难以管理） ，然而这只是最基本的一步，问题是对于一个博客文章，我们并不能直接在obsidian中直接新建一个空白的md文件，他还需要维护头部信息，如tags、categories等等，所以我们一般来说会使用hexo new (post) “博客名”的方式来创建一个自带头部信息的md文件，这里的post为default值，可以不要。括号中的参数不仅可以填post，还有draft、pages，分别对应scaffolds文件夹下的三个md文件，这三个文件即为使用hexo new时创建新文件所使用的模板，指定post所用的初始模板就是scaffolds下的post.md，以此类推。

于是为了合乎博客主题的要求，我们需要配置好属性齐全的模板文件并要在每次写作前hexo new一个md文件，然后才能进入obsidian进行编辑写作。同理写作完之后，我们还需要在MyBlog文件夹下运行一串hexo c+g+d才能完成一套基本的部署流程

还是太麻烦了，我写东西的时候一定要开着命令行然后反复输入hexo命令吗——所以我们引入第三方插件ShellCommands来解决这个虽然不难但有点麻烦的重复工作

shellcommands可以存储命令并将其链接到快捷键，我们只要设置好工作目录（在这里其实也就是仓库根目录）再定义需要的用户变量，使用时输入即可

介绍一下具体设置

在设置中下载完第三方插件Shell Commands，首先记得在Environment-Working directory设置好工作目录为博客根目录

命令1：生成新文件

_New一个Shell Command，此命令便可运行在cmd中（Environment中也可以设置别的环境），我们需要两个自定义变量：_type和_title，（用{{}}包裹），默认值分别为post和NewPost
在Preaction中整一个弹窗来设置

设置一下操作名称为New再绑定一下快捷键即可

现在直接使用 Ctrl+Shift+O 即可生成一个指定类型指定名称的新的模板文件

命令2：自动部署

和上面差不多，而且不用自定义变量，直接New一个Shell Command然后输入hexo c && hexo g && hexo d，再设置一下快捷键即可（我设置的是Ctrl+Shift+P ），这个推荐开一下执行确认弹窗防止误触。

流程总结

Ctrl+Shift+O生成一个新模板->填好模板信息写好博文内容->Ctrl+Shift+P直接发布

为啥不做个Hexo s自动调试捏？因为这个shell commands是非交互式的，不方便Ctrl+C结束进程，只能用taskkill强杀。这个流程适合已经比较熟悉博客内容和md格式追求效率用hhh
